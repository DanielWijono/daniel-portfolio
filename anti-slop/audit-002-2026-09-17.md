## Open findings

1. **LOW: Decorative Hallmark comment header restates the selector below it.** `R-31`
   - Reason: `public/index.html:8-10` reads `Hallmark · macrostructure: Stat-Led (luxury hero) · tone: signature · anchor hue: warm-bronze * nav: masthead · footer: statement-echo · genre: editorial · theme: Atelier`. This is process metadata, not a design decision with a written reason; it also self-labels the hero as "Stat-Led," naming the exact template pattern flagged in finding 2 below.
   - Fix direction: delete the header comment, or replace it with the one-line reasons `DESIGN.md` already documents.

2. **LOW: Hero-to-footer structure follows the generic SaaS template shape.** `R-05`
   - Reason: masthead → hero (eyebrow, H1, subhead, two CTAs) → stat band → work-card grid → experience list → skill-tag grid → footer statement is the standard AI landing-page skeleton (Hero+stats+feature-grid+footer-CTA), independent of the editorial palette layered on top.
   - Evidence: `public/index.html:141-296`. The page's own header comment names this "Stat-Led (luxury hero)," i.e. the stat band is a structural choice, not incidental.
   - Fix direction: fold the three stat numbers into the experience section next to the role that earned each one (97% crash-free next to the Quadrant job, 4 devs led next to the BNI job) instead of banding them as a standalone template section.

3. **MEDIUM: Hero eyebrow restates the headline.** `R-09`
   - Reason: `.hero-eyebrow` reads "Senior iOS Developer" (`public/index.html:143`), and `<h1>` on the next line opens with the same claim before adding fintech/enterprise context (`public/index.html:144`). The eyebrow carries no information the headline doesn't already state, matching the "eyebrow badge above the headline" pattern (label the headline already says).
   - Fix direction: drop the eyebrow, or replace it with something the headline doesn't cover (e.g. location, availability).

4. **MEDIUM: Arrow glyph on every external link with no stated purpose.** `R-08`
   - Reason: both `.work-link` entries append `↗` (`public/index.html:169`, `public/index.html:175`) as decoration. `DESIGN.md` documents no reason for the arrow.
   - Fix direction: remove it, or keep it and add a one-line reason to `DESIGN.md` (e.g. "signals the link leaves the site").

5. **LOW: Skill tags are full pill shape against a 3px-radius design system.** `R-11`
   - Reason: `.tag` uses `border-radius:20px` (`public/index.html:110`) while every other radius token in the file is `--radius-sm: 3px` or a 4-6px card radius. `DESIGN.md` documents "restrained corner radii (3px)... not enough to read as app UI" as the stated identity, which the pill tags contradict.
   - Fix direction: match the tag radius to the documented system (3-6px), or add a written reason for the one exception.

6. **LOW: Work / Experience / Skills / Education sections share one uniform internal shape.** `R-05`
   - Reason: each section is `section-head h2` followed by an identical grid pattern (`work-grid`, `job` rows, `grid-2` tag columns, `grid-2` edu columns). `DESIGN.md` declares RHYTHM 2 ("generous section spacing... no dense grid of cards"), but delivery reads as RHYTHM 1: no section varies in composition from its neighbors.
   - Fix direction: give at least one section a distinct internal layout (e.g. Experience as a running list without the label+content grid, Skills as inline prose instead of a tag grid) so RHYTHM 2 is visible, not just declared.

7. **LOW: Footer statement is generic inspirational copy with no written reason.** `R-31`
   - Reason: `.footer-statement` reads "Let's build something worth shipping." (`public/index.html:296`). It is not a listed buzzword or forbidden CTA string, but `DESIGN.md` gives no reason for this specific line, and it carries no content specific to this portfolio, industry, or the person behind it.
   - Fix direction: replace with a line that references something concrete from the page (fintech/enterprise iOS, the BNI role, the crash-free discipline), or write down why this exact sentence earns its place.
