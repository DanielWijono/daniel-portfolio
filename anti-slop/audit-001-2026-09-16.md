# Antislop audit 001

Date: 2026-09-16  
Mode: AFTER  
Scope: `index.html`, six public theme variants, `netlify.toml`, and the bundled CV

## Assessment

Overall result: **FAIL**

The default page has a credible editorial identity and avoids most common generated-UI decoration. Its warm paper palette, bronze accent, Fraunces display face, restrained radii, and content-led work and experience sections feel deliberate. The hard-gate failures are concentrated in mobile behavior, evidence discipline, and link accuracy rather than visual polish.

Design Read for this audit: senior iOS developer portfolio for recruiters and engineering leaders, using an editorial craft language. Inferred dial: **ENERGY 2 / RHYTHM 2 / MOTION 1**. These dials are not documented in the repository.

## Findings

1. **HIGH: Mobile controls are clipped instead of reflowed.** `R-03`
   - Reason: `html, body { overflow-x: clip; }` hides layout overflow while controls still extend beyond the viewport.
   - Evidence: at 390 px, the root `Contact` link ends at 397.9 px. At 320 px, the root body measures 398 px, `signature/` measures 359 px, and `luxury/` measures 353 px. The root and signature contact controls and the luxury and signature `Other themes` links are visibly cut off.
   - Affected source: `index.html:38`, `signature/index.html:40`, `luxury/index.html:36`.
   - Fix direction: reduce narrow-screen inline padding and gaps, allow the masthead and footer rows to wrap intentionally, then remove overflow clipping as a layout bandage.

2. **HIGH: Mobile navigation removes the page destinations.** `R-03`
   - Reason: the mobile state hides the section links rather than providing a usable mobile navigation pattern.
   - Evidence at 390 px: the root shows only `Contact`; `refined/`, `signature/`, `technical/`, and `utilitarian/` show only the contact action; `luxury/` shows no navigation link at all.
   - Affected source: `index.html:56`, `luxury/index.html:52`, `refined/index.html:58`, `signature/index.html:58`, `technical/index.html:82`, `utilitarian/index.html:56`.
   - Fix direction: keep the primary destinations visible when they fit, or provide a labelled menu that opens by tap and keyboard.

3. **HIGH: Mobile tap targets are below 44 by 44 px.** `R-03`
   - Reason: text links and compact CTAs use desktop-sized hit areas on touch screens.
   - Evidence at 390 px: 38 visible controls across the seven pages have either width or height below 44 px. Examples include the root `Contact` at 105 by 34 px, work links at 183 by 34 px, `austere/` hero links at 28 px high, `technical/` contact links at 29 px high, and footer links at 15 to 18 px high.
   - Fix direction: add block padding or a larger pseudo-element hit area while preserving the compact visual treatment, and leave space between adjacent targets.

4. **HIGH: Visible copy contains 61 U+2014 em-dash characters.** `R-02`
   - Reason: the rule forbids em dashes in shipped interface copy.
   - Evidence: every page uses them in the document title and date ranges; several hero paragraphs and the technical headline use them as sentence separators. `austere/` also generates them as list markers.
   - Affected examples: `index.html:6`, `index.html:161`, `austere/index.html:71`, `austere/index.html:101`, `technical/index.html:169`.
   - Fix direction: use periods or commas for sentence joins and plain hyphens for compact date ranges.

5. **HIGH: Several performance and reach claims are not supported by the repository evidence.** `R-36`, `R-38`
   - Reason: claims about audience scale and availability need a source, even when they sound plausible.
   - Evidence: the bundled CV supports `8+ years`, `97% crash-free`, and leading four developers. It does not support the root headline `millions of users`, the technical phrase `high-availability mobile apps`, or the repeated promise that work `stays up`.
   - Affected source: `index.html:139`, `index.html:291`, `technical/index.html:170`, `refined/index.html:130`, `signature/index.html:263`, `utilitarian/index.html:130`.
   - Fix direction: remove these claims, qualify them precisely, or add a real source that substantiates them.

6. **HIGH: The Quadrant work-card action does not match the work described.** `R-26`, `R-38`
   - Reason: a control must perform the action its label and surrounding content promise.
   - Evidence: the `Quadrant location-data app` card links `View on GitHub` to `github.com/DanielWijono/AndroidTimePickerSwiftUI`, which represents a component with a different name rather than the location-data app described by the card.
   - Affected source: `index.html:166-170`.
   - Fix direction: relabel the card around the open-source component, link to evidence for the described app, or remove the action.

7. **HIGH: `Other themes` is a dead-end promise on every variant.** `R-26`
   - Reason: the label promises a theme list or selector, but each link only returns to the root page, where no other theme choices are exposed.
   - Evidence: `austere/`, `luxury/`, `refined/`, `signature/`, `technical/`, and `utilitarian/` all use `href="../"`; the root has no theme navigation.
   - Affected examples: `austere/index.html:189`, `luxury/index.html:263`, `technical/index.html:300`.
   - Fix direction: add an actual theme index, rename the link to `Default portfolio`, or remove public theme navigation.

8. **MEDIUM: The technical variant stacks generic terminal signals without a written product purpose.** `R-01`, `R-06`
   - Reason: the dark phosphor palette, all-monospace typography, command syntax, `.log` and `.json` labels, `contact()`, comment syntax, and repeated green left borders form a familiar developer-theme costume rather than a specific portfolio identity.
   - Evidence: `technical/index.html:11`, `technical/index.html:57-87`, `technical/index.html:100-128`, `technical/index.html:154-179`.
   - Fix direction: retain only the motifs that help engineering readers scan evidence, then explain the purpose in the design direction.

9. **MEDIUM: Major visual techniques are named but not justified.** `R-01`, `R-06`, `R-10`
   - Reason: the Hallmark headers record macrostructure, tone, and hue, but they do not state why the palette, type pairing, blurred sticky navigation, or theme-specific layout serves the audience and hierarchy.
   - Evidence: each file begins with a style label, while no `DESIGN.md` or decision record contains the required one-line reasons or declared dials.
   - Fix direction: add a short design-direction file with audience, identity, palette, typography, dials, and one-line reasons for each major technique.

10. **LOW: Seven public variants dilute the canonical identity.** `R-20`, `R-31`
    - Reason: a portfolio should make one memorable argument, while this repository publishes several overlapping identities and near-duplicate pages.
    - Evidence: the root and `signature/` differ mainly in content and scale; `refined/` and `utilitarian/` share the same structure with token changes. The root does not explain whether the variants are experiments or user-facing choices.
    - Fix direction: choose one canonical public presentation and keep experiments unpublished, or make theme choice an intentional, accessible feature.

11. **LOW: Code comments contain decorative labels and opaque internal codes.** `R-31`
    - Reason: comments such as `N6 masthead`, `hero`, `panels`, and `Ft5 statement` either restate the selector below them or rely on undocumented shorthand.
    - Evidence: `index.html:47`, `luxury/index.html:45`, `technical/index.html:57`, `technical/index.html:84`, `technical/index.html:100`, `utilitarian/index.html:70`, `utilitarian/index.html:103`.
    - Fix direction: remove empty labels. Keep only comments that explain a non-obvious constraint or design decision. Comment-only changes must not alter executable code.

## What passes

- **Color contrast passes `R-25`.** Browser-computed checks found no failing visible text pair across all seven pages. The tightest normal-text case is the technical theme at 4.99:1.
- **Keyboard focus passes the tested portion of `R-32`.** The root page follows DOM order and gives each tested link a visible 2 px focus outline.
- **Navigation destinations pass `R-24`.** Every section link tested points to an existing section.
- **Interactive elements mostly pass `R-26`.** Contact, telephone, CV, social, App Store, and section links have real destinations. Findings 6 and 7 are the exceptions.
- **Evidence is stronger than it first appears.** The CV corroborates `8+ years`, `97% crash-free`, and leading four developers.
- **Visual restraint passes the main UI checks.** There are no gradients, glows, fake testimonials, decorative emoji, generic FAQ blocks, or page-wide shadow systems. Glass is limited to one navigation surface per applicable page.
- **Motion is appropriately calm.** The pages use hover and active feedback only and include reduced-motion handling.
- **No script-patching issue was found.** The project is direct HTML and CSS with no patch helper.
- **The browser console stayed clean.** No warnings or errors appeared while loading all seven routes.

## Additional accessibility note

Four pages contain two `<main>` elements (`/`, `refined/`, `signature/`, and `utilitarian/`), while the root, luxury, and signature mastheads are generic `<div>` containers instead of navigation landmarks. Keyboard operation still works, so this is not scored as an `R-32` failure, but the landmark structure should be corrected for screen-reader navigation. The long pages also have no skip link.

- Purpose-Gate: **FAIL** due to undocumented rationale and the technical-theme trope cluster.
